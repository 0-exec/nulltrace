Mirai

Type: IoT Botnet Malware

Overview

Mirai is a malware family first identified in 2016. It primarily targets Internet of Things (IoT) devices, including routers, IP cameras and digital video recorders. It infects vulnerable Linux-based devices and turns them into remotely controlled bots. These compromised devices form a botnet that attackers can use to conduct large-scale Distributed Denial-of-Service (DDoS) attacks. Mirai became widely known following several major attacks against internet infrastructure in 2016.

Technical Details

Mirai spreads by scanning the internet for exposed devices with Telnet services. It attempts to access these devices using a built-in list of common default or hardcoded usernames and passwords. When authentication succeeds, a separate loader component can download and execute a malware binary suited to the target device's processor architecture. Infected devices communicate with command-and-control infrastructure and can receive instructions to participate in DDoS attacks.

Its observed capabilities included:

  • Scanning for exposed IoT devices
  • Brute-forcing Telnet services using common credentials
  • Infecting Linux-based embedded devices
  • Using architecture-specific malware binaries
  • Connecting compromised devices to a botnet
  • Receiving commands from remote infrastructure
  • Launching distributed denial-of-service attacks

Botnet Operation

Mirai uses a scanning and infection process to expand its botnet. First, it searches for devices exposing Telnet services on commonly used ports. It then attempts authentication using predefined credentials. Successfully compromised devices are reported to infrastructure used by the malware's loader. The loader installs a binary compatible with the device's architecture. Once infected, devices can receive attack instructions and generate large volumes of network traffic against selected targets.

Historical Timeline

  • August 2016: Mirai scanning activity is first observed.
  • September 2016: A Mirai botnet launches a major DDoS attack against the Krebs on Security website.
  • September 30, 2016: Mirai source code is publicly released.
  • October 21, 2016: A Mirai-based attack targets DNS provider Dyn, disrupting access to many popular online services.
  • Following months: Multiple Mirai variants emerge as other actors reuse and modify the publicly released code.

Impact

Mirai was responsible for several major DDoS attacks in 2016. One widely reported incident targeted DNS provider Dyn on October 21. The disruption affected access to numerous websites and online services. The attack demonstrated how poorly secured IoT devices could be combined into a powerful attack infrastructure. The public release of Mirai's source code also contributed to the development of numerous variants, extending its influence beyond the original botnet.

Research Notes

Mirai is a useful case study for understanding IoT malware propagation and botnet architecture. During analysis, researchers can examine binary architecture, embedded credential lists, strings, network indicators and communication patterns. Important behavioral characteristics include Telnet scanning, authentication attempts against default credentials, communication with loader infrastructure and subsequent C2 activity. Researchers should also consider that the original Mirai infection was generally memory-resident and did not persist across device reboots. However, vulnerable devices could be reinfected if their security weaknesses remained unaddressed. Malware samples should only be handled in an isolated analysis environment.
