Introduction to Dynamic Malware Analysis

Category: Malware Analysis

Level: Beginner

Introduction

Dynamic malware analysis is the process of observing a program while it is running in a controlled environment.

Unlike static analysis, which examines a file without executing it, dynamic analysis focuses on the actions and behavior of a program during execution.

Analysts use this approach to understand how suspicious software interacts with the operating system, modifies files, communicates over networks and creates or modifies processes.

What Can Analysts Observe?

During dynamic analysis, researchers monitor different aspects of system activity. Common areas of investigation include:

  • Process creation and termination
  • File creation, modification and deletion
  • Registry modifications
  • Network connections and DNS requests
  • Loaded libraries and system activity
  • Changes to system configuration

Setting Up an Analysis Environment

Dynamic malware analysis should never be performed directly on a normal everyday computer.

Analysts use isolated environments to reduce the risk of accidental infection, data loss and unintended communication with external systems.

A common approach is to use a virtual machine (VM). A VM runs an operating system inside another operating system, allowing researchers to create a separate environment for analysis.

Important considerations include:

  • Use a dedicated virtual machine for analysis.
  • Take a clean snapshot before each investigation.
  • Disable shared folders and shared clipboard functionality.
  • Avoid connecting the analysis environment to personal accounts or sensitive data.
  • Use controlled networking, with external access disabled by default.
  • Revert the virtual machine to a clean snapshot after analysis.

Network isolation is particularly important. Host-only networking or a disconnected virtual network can be used for basic observation. More advanced network simulations require carefully configured lab infrastructure.

A virtual machine is not a perfect security boundary. Unknown or potentially evasive malware should only be handled in a properly isolated research environment.

Common Tools

Malware analysts use several tools to observe and document program behavior.

  • Process Monitor (Procmon): Monitors filesystem, registry and process activity on Windows.
  • Process Explorer: Provides detailed information about running processes, loaded modules and process relationships.
  • Wireshark: Captures and analyzes network traffic.
  • Autoruns: Helps identify programs and components configured to start automatically.
  • Regshot: Compares registry snapshots to identify changes between two system states.

Understanding Process Activity

Processes are one of the first areas analysts investigate during dynamic analysis.

A process represents a running instance of a program. By observing process activity, analysts can identify which applications are launched, which child processes are created and how programs interact with the operating system.

For example, Process Monitor can record process creation events and other system activity. This information helps researchers understand the sequence of actions performed by a program.

Monitoring Filesystem and Registry Changes

Some malicious programs attempt to modify files, create directories or change Windows Registry settings.

These actions can provide useful indicators of program behavior.

Analysts can use Process Monitor to observe filesystem and registry operations. Tools such as Regshot can also compare registry states before and after a test.

Changes to startup locations, system configuration and application settings may be particularly relevant when investigating persistence mechanisms.

Network Activity Analysis

Network monitoring is another important part of dynamic malware analysis.

Some malware communicates with external infrastructure to receive instructions, transmit information or download additional components.

Analysts examine network activity to identify:

  • DNS queries
  • IP addresses and destination ports
  • HTTP and HTTPS connections
  • Unusual communication patterns
  • Repeated connection attempts

Wireshark allows researchers to capture and inspect network packets. In an isolated lab, simulated services can also help researchers observe how software behaves without allowing communication with real external infrastructure.

Observing Program Behavior

Dynamic analysis is not simply about collecting events. Analysts need to understand how individual actions relate to one another.

For example, an investigation might reveal that a program creates a new process, writes files to a directory and attempts to establish a network connection.

Each observation provides additional context about the program's behavior. However, individual events should not automatically be considered malicious. Legitimate software can perform many of the same operations.

Limitations of Dynamic Analysis

Although dynamic analysis provides valuable behavioral information, it also has limitations.

  • Environment awareness: Some malware can detect virtual machines or analysis environments.
  • Delayed execution: Certain behaviors may only appear after a specific amount of time or under particular conditions.
  • Incomplete observations: Analysts may not observe every possible behavior during a single investigation.
  • Isolation: Restricted networking can prevent certain behaviors from appearing.

For these reasons, dynamic analysis is most effective when combined with static analysis and other investigation methods.

Conclusion

Dynamic malware analysis allows researchers to observe how programs behave during execution and how they interact with their environment.

By monitoring processes, filesystem activity, registry modifications and network communication, analysts can develop a better understanding of suspicious software.

Combined with static analysis, dynamic analysis provides a more complete approach to malware investigation.
